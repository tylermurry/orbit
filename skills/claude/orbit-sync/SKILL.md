---
name: orbit-sync
description: Reconcile the active Orbit contract with implemented code and verification evidence. Use /orbit-sync to record the reviewed branch tip for an optional PR check.
disable-model-invocation: true
---

1. Use Orbit MCP `get_status` to identify the open project, contract path, and branch. Refresh Git status and confirm the repository and branch in the terminal. If the Orbit MCP tools are unavailable, ask the user to open their project in Orbit and connect its MCP server. Preserve any unsaved user edits and resolve them with the owner before updating Actual.
2. Read `get_proposal`. Use its pinned baseline if it applies, an explicitly requested baseline when there is no applicable proposal, or the merge base with the repository's base branch. Review the complete implementation delta and relevant tests. The approved proposal is context for reconciling missing, changed, and unexpected outcomes. Check source and test files and use actual execution results when reporting pass or fail. Preserve existing stable IDs. Match newly implemented tests to their proposal IDs when they represent the same test. Remove a legacy placeholder flag only once the real test exists.
3. Use Orbit MCP `apply_edits` and `save_file` as needed to reconcile the actual contract. Keep the proposal untouched. Summarize what changed, what was unverified, and where the implementation differs from the approved proposal. Use `view_changes` for Actual or Actual vs. Proposal when available.
4. For a PR-ready sync, record the named branch and reviewed HEAD before reviewing. The reviewed code must be committed. Uncommitted implementation changes are eligible for local preview only. From a clean index and reviewed implementation, commit just the updated Orbit contract if it changed. If the contract needed no edit, retain the reviewed HEAD. Before tagging, ensure the branch is unchanged, the final tip is the reviewed commit or its direct child changing only the actual contract, and the saved contract matches that commit. Ensure no staged, unstaged, or untracked implementation changes remain. Ignore the project's `orbit.proposal.json` when checking whether the implementation tree is clean. If any check fails, report local preview only and leave the tag where it is.
5. Set `refs/tags/orbit/sync/<branch>` to the explicitly verified final commit with `git update-ref`. Use the previous tag value as a compare-and-swap precondition, or an all-zero value for a new ref. Report the local sync point. When the user authorizes pushing, push the branch and exact tag together atomically to the PR head repository, with an explicit lease on the remote tag's observed prior value. If the push fails, report it and explain that the remote PR check has not been satisfied.
